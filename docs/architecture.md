# MDS: децентрализованный поиск

MDS — поисковая система. Публичное имя — Пчелопоиск. Одна нода по-прежнему называется пчела. Ноды обходят публичные страницы, хранят куски индекса и отвечают на запросы. Это не каталог продавцов и не прокси.

Одна нода — пчела. Несколько соединённых нод — рой. Улей — региональный вход, домен, с которого люди ищут. Пасека — страна, сеть ульев. В программе процесс по-прежнему называется `mds`, робот представляется как `MDS-Bot`.

Сервер, компьютер и старый телефон говорят одним протоколом. В этом репозитории работает одиночная нода: обход, гибридный индекс и сайт со строкой поиска. Телефон описан схемой и подключается тем же бинарником позже.

## Строка поиска

Страница — [`apps/mds-web`](../apps/mds-web). Её отдает процесс `mds node` на сервере или компьютере. Адрес по умолчанию: `http://127.0.0.1:8080/`.

На странице одна строка, кнопка «Найти» и список ссылок. Знак «Пчелопоиск» стоит по центру. В подвале написано, сколько разных сайтов и страниц сейчас в индексе этой ноды. Сайт сам индекс не хранит: текст уходит в ноду, нода считает эмбеддинг запроса и ищет в локальном шарде.

Старый телефон не публичная точка входа. В APK будет тот же экран для владельца, а процесс ноды будет дополнительной репликой в общей сети.

## Как ищется запрос

Поиск гибридный.

1. Текст страницы при обходе кодируется моделью `multilingual-e5-small` (ONNX, 384 измерения). В SQLite вектор лежит как int8 и масштаб. Префиксы модели: `passage:` для страницы и `query:` для запроса.
2. Рядом SQLite FTS5 (BM25) хранит заголовок и текст, чтобы точные названия не терялись.
3. Запрос идёт обоими способами. Списки склеивает reciprocal rank fusion, константа k = 60. Выдача не режется по языку страницы: русский и английский текст лежат в одном индексе. Слова при этом разные: honey не отвечает на запрос «мёд».
4. Если во фразе есть коммерческое намерение («купить», «цена», «заказать» и похожие), известный хост маркетплейса получает штраф. Прямой сайт остаётся выше. Индекс при этом общий, по страницам, а не по карточкам компаний.

Между нодами ключ шарда — это хеш домена плюс смысловой бакет. Бакет — 16 знаков скалярного произведения эмбеддинга с фиксированными гиперплоскостями (locality-sensitive hashing). Близкие по смыслу страницы попадают в один бакет. Число 3 — это сколько держателей бакета спросить и сколько копий шарда назначает карта, а не «три сервера на всю сеть». Пока подписанной карты нет, страница лежит на той ноде, которая её обошла. Соседи своего края объявляют бакеты через `/peer/status`. Улей спрашивает держателей бакета, не больше трёх, сначала тех, кто ответил быстрее. Другой край открывается кнопкой «Искать в …»: браузер идёт на улей этого края, а эта нода чужой индекс не собирает. Ноды говорят протоколом MDS Wire v1 на `/peer/v1/`, с подписью своей пары ключей. MCP — дверь владельца к своей ноде, не разговор нод между собой.

Повтор одного и того же запроса нода помнит 5 минут, не больше 64 разных текстов. В этот список не входят адреса людей.

Регион страницы читается из её текста: область, край, республика или город вроде Камышина. Если место не названо, пометки нет. Адрес датацентра и адрес хостинга сайта регионом не считаются. Человек выбирает свой край кнопкой настроек у строки поиска: там плашка с текущим краем. Улей может подставить свой край флагом `--region`. Сначала идут страницы этого края, ниже — остальные. Адрес человека в журнал не пишется. Карта, часы работы и маршрут в выдачу не входят.

Под строкой поиска стоят вкладки типа страницы: новости, органы власти, работа, услуги, медицина, товары, документы, картинки и видео. Вкладка — это тот же индекс, разрезанный по типу, который читается со страницы. Рубрикатор Яндекса не копируется. Изделия завода лежат в индексе. Ассортимент интернет-магазина нода не хранит: список под строкой запрашивает браузер, если магазин разрешил такое чтение. Статьи перечисленных СМИ в индекс тоже не пишутся. На вкладке «Новости» кнопка «Раскрыть» показывает пару строк свежих заголовков: улей читает их RSS в этот момент и не сохраняет. Браузер чужую ленту сам не открывает, издания это закрывают. Обычный сайт обходится до 100 страниц. Если в `/llms.txt` или `/llms.md` перечислены ссылки своего сайта, индексируются они, не больше ста, а остальные адреса этого сайта в очередь не ставятся. Все страницы принимаются только от сайта, на котором стоит своя пчела.

## База

Слова и текст страниц лежат в одном файле SQLite: FTS5 с BM25 для точного совпадения и квантованный вектор рядом со страницей. На тысячах и десятках тысяч страниц поиск по словам занимает доли секунды. Отдельный сервер базы на каждой пчеле ноду не ускорит и сделает старый компьютер тяжелее.

Смысловой поиск сравнивает вектор запроса с векторами бакета. Если в бакете мало страниц, сравниваются все векторы шарда. На полутора тысячах страниц это незаметно. На сотнях тысяч страниц в одном шарде узким местом станет этот перебор, не таблица слов.

Дальше база растёт так:

- Слова остаются в SQLite.
- Векторы переводятся на индекс ближайших соседей HNSW (`usearch` или `sqlite-vec`), когда шард станет большим. Хранить их в f16 незачем: в базе они уже int8, один байт на число, а f16 занимает два. Гигабайт памяти съедает сама модель, не список векторов страниц.
- Полнотекстовый движок вроде Tantivy подключается ещё позже, когда слов в одном шарде станет очень много.

Замена SQLite на отдельную сетевую базу в план не входит: у пчелы один файл индекса, его можно перенести вместе с нодой.

## Модель эмбеддингов

Сейчас стоит `multilingual-e5-small`, модель 2024 года. Она считает 384 числа на процессоре, занимает в памяти около 1 ГБ и понимает русский и английский. Её выбрали по размеру ноды: улей на 8 ГБ и пчела на 4 ГБ её держат, видеокарта не нужна. Это рабочая модель текущего размера, не потолок качества.

Канонический файл весов лежит на улье, в каталоге `data/models/swarm`. Полная нода забирает его оттуда при запуске и сверяет подпись и контрольные суммы. Hugging Face для роя не источник: новая нода без локального файла и без манифеста улья модель оттуда не качает. Уже работающая нода, у которой веса уже лежат в `data/models`, открывает этот каталог, пока улей не выложил манифест. Смена файла не пересчитывает страницы сама: в журнале будет строка, что старые векторы больше не годятся. Лёгкая пчела модель не запрашивает. Ссылки на веса на странице «Скачать» нет. Закрытый ключ выпуска модель не сопровождает: оператор подписывает каталог у себя, улей только отдаёт файлы.

Дообучение возможно на парах «запрос — нужная страница». Журнал ноды хранит текст запроса и числа выдачи, без отметки, какую ссылку человек открыл, и без адреса человека. Учиться на этих строках нечему. Своя дообученная модель перестанет совпадать с векторами соседних нод: общий шард держится на одной и той же модели. Смена модели означает пересчёт всего индекса.

Сильнее в той же семье — `multilingual-e5-base` и `multilingual-e5-large`. Из более новых моделей для многих языков — `bge-m3`, `gte-multilingual`, Jina embeddings v3, Qwen3-Embedding. Они точнее на сложных фразах, требуют больше памяти и времени на ответ. Их имеет смысл ставить, когда улей вырастет и все ноды роя смогут перейти на одну новую модель вместе.

## Роли

- Сервер и компьютер держат крупные шарды и отдают сайт со строкой поиска.
- Старый телефон — дополнительная нода для владельца, не публичный вход. В программы вписана доверенная нода `https://45.158.46.52`. Новая версия сообщается подключённым нодам, на странице поиска появляется «Нужно обновиться». Оболочка телефона — `apps/mds-android`: тот же адрес и то же сообщение. Готового APK нет.
- Чужой трафик через телефон не проходит. Прокси и обход блокировок не входят в систему.

## Зачем несколько нод

Карта сети назначает шарду три машины одного края. Пока в крае одна нода, копия одна: это не три одинаковые базы. Новая машина сначала получает снимок, затем пакеты изменений после известной ревизии. Пакет принимается только после проверки хеша. Поиск спрашивает одну живую копию и переходит на следующую, если первая молчит. Сто нод в одном городе делят индекс на шарды, а не держат сто полных копий.

Журнал запросов остаётся на той ноде, которая ответила, и не уезжает в общий центр. У сети нет компании-владельца: свой адрес поиска может открыть регион, компания или человек со своим сервером. Нода без соседа отвечает только своим индексом.

Нагрузка начинает делиться, когда нод становится больше трёх. Четвёртая берёт другие шарды, а не ещё одну копию всего. Запрос идёт на держателей нужного шарда, не больше чем на три копии, и сначала на ту, которая в прошлый раз ответила быстрее. Реплика, которая медленнее самой быстрой втрое и больше чем на 400 мс, в этот круг не попадает, если жива хотя бы ещё одна.

Пчела за динамическим адресом сама соединяется с ульем (`--lite`, `--site`, `--hive`) и отдаёт ему свежие страницы своего сайта и несколько чужих адресов из очереди. Подтверждение — файл `/.well-known/pchela.txt` на сайте. Белый статический IP нужен улью, на который смотрит домен. Домашней пчеле достаточно исходящего интернета. Кабинет `https://admin.<домен-ноды>/operator` показывает страницы, очередь, размер базы, поиски за минуту, карту, ключевые запросы, заходы, время, отказы и ошибки поиска и выдаёт ключ MCP. Адреса людей туда не пишутся, заход не склеивается с текстом запроса. Публичный сайт этот путь не содержит: его слушает отдельный порт, который открывает только nginx имени `admin`. Пароль на диск не пишется, в файл окружения кладётся Argon2id-хеш. Как поставить два входа: [deploy-nginx.md](deploy-nginx.md).

## Сервер

Видеокарта не нужна: модель `multilingual-e5-small` считает векторы на процессоре и занимает в памяти около 1 ГБ. Тяжёлым на диске становится текст страниц, не векторы.

| Нода | Машина |
| --- | --- |
| Первая публичная, десятки тысяч страниц | 4 ядра, 8 ГБ памяти, SSD 100 ГБ |
| Вторая и третья, если на них тоже открывают поиск | те же 4 ядра, 8 ГБ, SSD 100 ГБ |
| Вторая и третья, если они только отвечают соседним нодам | 2 ядра, 4 ГБ, SSD 100 ГБ |
| Старый компьютер, который только отвечает соседним нодам | те же 2 ядра и 4 ГБ; диск по размеру индекса, для десятков тысяч страниц — около 100 ГБ |
| Крупный шард, около миллиона страниц | 8 ядер, 16 ГБ, SSD 500 ГБ |
| Телефон | маленький шард, не публичный вход |

Обычного канала хватает: страницы качаются с паузой, ответ человеку — короткая HTML-страница. Узкий канал фильтра вроде 0.5 Мбит/с для публичного улья не подходит. Одному улью хватает одного IP. Предпочтительнее SSD: на жёстком диске ответы медленнее.

Старый компьютер, который уже не нужен как рабочее место, запускает тот же `mds node` и входит в сеть адресом соседа. Свой домен ему не нужен. Модель занимает около 1 ГБ, поэтому машина с 2 ГБ памяти и 32-битная система шард не удержат. Пока страниц тысячи, хватает небольшого диска. Когда индекс вырастет до десятков тысяч страниц, на этой ноде нужно около 100 ГБ, потому что при трёх нодах она хранит весь индекс. Жёсткий диск вместо SSD подходит, ответы будут медленнее.

## Трафик

Один улей принимает людей, считает вектор запроса и ищет у себя. Обход сайтов идёт в фоне и ответ человеку не держит. Потолок одного улья — обычный поток и десятки тысяч страниц на машине из 4 ядер и 8 ГБ. Миллион страниц в крупном шарде — машина из 8 ядер, 16 ГБ и SSD около 500 ГБ.

Трафик растёт добавлением машин, без центральной базы:

- Больше людей в регионе — второй и третий улей, со своим доменом или с тем же. Человек попадает на один из них. Журнал остаётся на ответившем улье.
- Больше страниц — с четвёртой пчелы индекс делится на разные шарды. Запрос идёт к трём держателям нужного куска, не ко всем машинам.
- Домашние компьютеры и телефоны чужой трафик не принимают. Они обходят страницы и отдают их улью. Белый адрес нужен только ульям.
- Когда ответов станет много, повтор запроса уже закрыт коротким кэшем. Дальше ускоряется перебор векторов: индекс HNSW из раздела «База». Слова при этом остаются в SQLite.

## Пчела на сервере сайта

Сервер, на котором уже живёт сайт, обычно маленький. У ТехноВелеса это 2 ядра, 4 ГБ памяти и 20 ГБ диска. У сайта лаборатории DARTA — 2 ядра, 3 ГБ и 20 ГБ. Полная нода туда не встаёт: модель занимает около 1 ГБ, а общий индекс при трёх копиях — десятки гигабайт. На машине с 3 ГБ рядом с работающим сайтом модели не остаётся места.

Свободное место на таком сервере занимает лёгкая пчела. Она не открывает поиск для чужих людей, не грузит модель и не хранит чужой индекс. Человек остаётся на улье: сервер сайта его не перекидывает и чужой поиск через себя не пропускает.

Ноды общаются так:

1. Лёгкая пчела кладёт на свой сайт `/.well-known/pchela.txt`: одна строка, имя, которое она печатает при запуске.
2. Она представляется улью: `POST /peer/join`. Улей читает карточку и запоминает сайт.
3. Улей отдаёт ей до четырёх чужих адресов из очереди обхода: `GET /peer/work`. Адреса выбирает улей.
4. Пчела скачивает эти страницы и свои, затем возвращает текст: `POST /peer/pages`. Чужой адрес, который улей не выдавал, не принимается.
5. Улей считает векторы и кладёт страницы в индекс. Остановить пчелу можно в журнале улья: сайт вычёркивается, очередь ей больше не выдаётся.

Цикл — раз в десять минут. Пауза между загрузками не меньше двух секунд, чтобы не мешать сайту на той же машине. Полные пчёлы отвечают на поиск, только если их адрес записан у соседа. Лёгкая пчела поиск не обслуживает: у неё нет индекса. Общий пароль для входа не используется. Что каждая роль получает за свою машину: [rewards.md](rewards.md).

```text
mds node --lite --site https://адрес-сайта --hive https://45.158.46.52
```

Сайт, чья пчела соединилась с ульем, в выдаче получает значок «держит пчелу» и множитель 1.05 к уже посчитанному счёту. Это подъём среди близких результатов. Совпадение слов, которое явно сильнее, остаётся выше: результат примерно с десятого места на первое от этого множителя не перескакивает. Вес «топ-100 сайтов» по-прежнему не используется.

## Пакеты

| Пакет | Роль |
| --- | --- |
| `mds-types` | Страница, хит, вектор int8, размерность 384 |
| `mds-wire` | Запрос с вектором и ответ top-k |
| `mds-dht` | Хеш домена, смысловой бакет, репликация 3, локальный каталог |
| `mds-crawl` | Загрузка, robots.txt, sitemap, SEO-разметка, пауза, User-Agent `MDS-Bot`, SimHash |
| `mds-embed` | ONNX-модель, вектор страницы и вектор запроса |
| `mds-index` | SQLite FTS5 и квантованные векторы |
| `mds-rank` | Склейка BM25 и косинуса, штраф маркетплейса |
| `mds-node` | Обход, индекс, HTTP, приём подписанного обновления |
| `mds-update` | Подпись релиза и замена своего бинарника |
| `mds-cli` | Команды `mds node`, `mds keygen`, `mds publish` |
| `apps/mds-web` | HTML страницы поиска |
| `apps/mds-android` | Схема APK, без сборки |

Краулер называет себя, читает `robots.txt` и ждёт между запросами к одному внешнему сайту. Для `127.0.0.1` пауза нулевая, чтобы локальная проверка не простаивала. Обхода защит и маскировки под браузер нет.

## 152-ФЗ

В индекс попадают публичные страницы. Аккаунт владельца телефона туда не пишется. Журнал запросов не связывается с личностью и не уезжает на отдельный центральный сервер. Согласие в будущем APK — только на хранение шарда и обход публичных страниц.

## Запуск одной ноды

Нужны Rust и файл `data/onnx/onnxruntime.dll` версии 1.20 (библиотека ONNX Runtime для Windows x64). Модель эмбеддингов полная нода забирает с улья в `data/models/swarm`. Пока манифест на улье не выложен, нода открывает уже скачанный локальный каталог и за новыми весами в сеть не ходит.

Каталог проекта содержит нелатинские буквы. Сборщик MinGW не открывает такие пути, поэтому объектные файлы кладутся в латинский каталог:

```text
$env:CARGO_TARGET_DIR = "C:\Users\artem\mds-target"
cargo run -p mds-cli -- node
```

Нода обходит файлы из `fixtures/` через локальный HTTP, строит индекс в `data/mds.db` и открывает поиск на `http://127.0.0.1:8080/`.

Проверка:

- `MDSBOLT42` — точное слово, страница крепежа, бейдж «слова».
- `как лечить собаку` — на странице про ветеринарную помощь этих слов нет, её поднимает вектор, бейдж «смысл».

Свой сайт улья отдаёт `robots.txt`, `sitemap.xml`, `/llms.txt` и `/llms.md`. В карточке коротко сказано, что это Пчела, и перечислены открытые страницы. Журнал `/operator` и протокол `/peer/` в карту и в обход не входят. Подписанный архив Windows появляется на `/download`, только когда оператор его опубликовал. Исходный код указан отдельно: https://github.com/artemklimovich/mds.

Реальный интернет начинается со списка адресов, по одному URL в строке. Образец: `examples/seeds.example.txt`. Свои сайты в этом списке держат выдачу по нашим проектам. Государственные сайты стоят там же отдельным блоком: портал госуслуг, Роскомнадзор и сайты органов, на которые ведут официальные перечни. Отдельной категории «государственные и муниципальные» в индексе нет, регион по-прежнему читается из текста страницы. Отдельно стоят чужие спички: страница союза, на которой у членов указан их собственный сайт. Обход забирает эти ссылки и ставит чужие сайты в очередь. Тестовые страницы из `fixtures/` в этот запуск не мешаются. Нода читает `robots.txt`, строки `Sitemap` и `Crawl-delay`, карточку `/llms.txt` (если её нет — `/llms.md`) и страницы `.md`. Краткий текст карточки добавляется к страницам того же сайта, а сам файл тоже попадает в индекс. Файлы `.mdx` не читаются. Со страницы забирается текст, JSON-LD, микроразметка `itemprop`, Open Graph, Twitter Card, Dublin Core, `meta description`, `keywords` и `canonical`. `noindex` и заголовок `X-Robots-Tag` не попадают в индекс, `nofollow` не ставит ссылку в очередь. Ответ 404 или 410 и страница с заголовком «не найдено» из индекса убираются. Баннер cookie и служебная фраза про webhook в текст страницы не записываются. Ссылка, в пути которой уже сидит другой адрес, в очередь не ставится. Чужой сайт можно поставить в очередь со страницы «Добавить сайт». Нода сначала открывает его и читает robots.txt. Если обход запрещён, страница не открывается или закрыта noindex, адрес в очередь не ставится, а на странице написано, что поправить. Карточка llms.txt, карта сайта и свой текст страницы в эту проверку входят как рекомендации. По умолчанию нода остаётся на том же сайте. Чужие домены: `--follow-external`.

```text
cargo run -p mds-cli -- node --seeds urls.txt --max-pages 100 --listen 127.0.0.1:8080
```

Повторный запуск не качает страницы заново. Полный обход заново: `--recrawl`.

Новая версия передаётся между нодами только с подписью. Секретный ключ издателя лежит в `data/release.key` и в репозиторий не входит. Публичная половина вшита в сборку. Файл без этой подписи нода не запускает.

```text
cargo build -p mds-cli --release
mds publish --key data/release.key --bin target/release/mds --version 0.1.1 --out data/releases
mds publish --key data/release.key --bin mds.exe --version 0.1.1 --out data/releases/windows
mds publish-model --key data/release.key --dir data/models/swarm
mds node --peers http://10.0.0.8:8080
mds node --lite --site https://адрес-сайта --hive https://45.158.46.52
```

Нода, у которой в `data/releases` уже лежит подписанный файл Linux новее её самой, перезапускается и отдаёт этот файл по `/peer/update`. Соседи из `--peers` забирают его, проверяют подпись и делают то же самое. Проверка повторяется каждые 6 часов. Файл Windows лежит отдельно, в `data/releases/windows`, и улей его не запускает: иначе машина подменила бы себя чужой программой. Запрос указывает систему: `/peer/update?os=linux` или `/peer/update?os=windows`. Без параметра отдаётся Linux. `onnxruntime.dll` рядом с программой обновление не заменяет. Лёгкая пчела по таймеру файл не меняет. Хозяин машины запускает `mds update --hive https://beesearch.ru`: команда забирает файл своей системы, сверяет подпись и ставит его на место, службу после этого перезапускают. Архив со страницы загрузки сам программу не подменяет. Готовые архивы улей отдаёт из `data/downloads`: `/download/pchela-linux-x64.tar.gz` и `/download/pchela-windows-x64.zip`. Рядом у каждого адреса есть `.sha256`. Копия на GitHub остаётся запасной ссылкой.
