# Два входа полной ноды

Публичный сайт и кабинет — разные имена. У адреса из одних цифр поддомена `admin` нет: сначала нужен домен, который указывает на машину, и сертификат на имя `admin` этого домена.

Программа слушает только себя:

- `127.0.0.1:8080` — поиск, страницы сайта и протокол нод `/peer/`;
- `127.0.0.1:8081` — кабинет `/operator`, вход `/login` и MCP `/mcp`.

Второй порт открывается, только если заданы `MDS_ADMIN_USER` и `MDS_ADMIN_PASSWORD_HASH`. Пустые значения кабинет не поднимают. Лёгкая пчела его не открывает.

Хеш печатает команда `mds admin-password`: она спрашивает пароль без эха. В файл окружения кладётся строка хеша, не сам пароль. Файл читает только root, права `0600`. Открытый пароль не пишется ни в unit-файл, ни в командную строку.

Пример файла `/etc/mds/admin.env`:

```
MDS_ADMIN_USER=keeper
MDS_ADMIN_PASSWORD_HASH=$argon2id$...
```

Когда у ноды уже есть домен, nginx основного имени проксирует на `8080`, а имя `admin` — на `8081`. Пока домена нет, тот же сайт по IP отдаёт кабинет только по пути `/admin` и проксирует этот путь на `8081`. `/operator` и `/mcp` в корне публичного сайта по-прежнему отсутствуют. Сессия кабинета на IP ограничена путём `/admin` и на поиск не уходит. Заголовки прокси доверяются только от локального nginx, потому что оба порта слушают `127.0.0.1`.

Сертификат нужен на оба имени. Сессия кабинета ставит cookie `Secure`, `HttpOnly`, `SameSite=Strict` и живёт только на имени `admin`.

Карта сети лежит в `data/network.json`. В маршрутизацию входит только карта с подписью ключа выпуска. Кабинет готовит текст, подпись ставится отдельно, закрытый ключ выпуска на ноду не кладётся.
